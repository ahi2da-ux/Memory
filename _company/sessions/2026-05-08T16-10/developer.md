## 📋 E2E 검증 실행 계획 및 프레임워크 (Immediate Execution Plan)

**목표:** 기능 작동 여부 $\rightarrow$ **수익화 목표 달성 가능성(ROI)** 관점의 리스크 검증을 통해 핵심 출시 기준(P0/P1) 확보.

### 1. 테스트 범위 정의 (Scope Definition)
모든 테스트는 다음 세 가지 핵심 루프를 중심으로 설계합니다:
1.  **인증 및 접근 (Auth Flow):** 로그인, 세션 유지, 권한 확인.
2.  **가치 생성 (Value Generation):** 정보 제보 $\rightarrow$ 포인트 적립 로직 실행.
3.  **가치 교환 (Value Exchange):** 포인트 사용/챌린지 연동 $\rightarrow$ 보상 루프 완성도.

### 2. 핵심 E2E 테스트 시나리오 목록 (Test Scenarios)

| ID | 모듈/흐름 | 테스트 시나리오 상세 내용 | 검증 목표 (ROI 관점) | 예상 결과 지표 | 우선순위 |
| :--- | :--- | :--- | :--- | :--- | :--- |

| **T-02** | Auth | 권한 분리 테스트: 일반 사용자 vs. 관리자(또는 제보 승인자) 접근 시도. | 보안 및 권한 제어의 정확성 검증. | 권한 없는 API 호출 실패 확인. | P0 (필수) |
| **T-03** | Data Flow (핵심) | 정보 제보 $\rightarrow$ 포인트 적립 프로세스 전체 실행 (사용자 입력부터 DB 반영까지). | **가치 생성 루프의 정확성 검증.** | 포인트 DB 기록과 사용자 UI 표시의 완벽한 동기화. | P0 (최우선) |
| **T-04** | Data Flow (Loop Closure) | 적립된 포인트를 활용하여 챌린지(예: 1억 챌린지)에 사용하고, 다음 제보 활동으로 연결 시도. | **가치 교환 메커니즘의 매끄러움 검증.** | 포인트 차감 및 다음 단계 활성화 로직이 오류 없이 연동됨. | P0 (최우선) |
| **T-05** | Data Consistency | 모든 핵심 데이터(사용자 정보, 포인트 잔액, 챌린지 상태)가 Supabase 계정 기준으로 완벽히 동기화되는지 최종 확인. | 전체 시스템의 신뢰성 확보. | DB 레코드 일치 여부 (Hash Check). | P1 |

### 3. 데이터 정합성 검증 전략 (Data Integrity Strategy)

모든 E2E 테스트는 **데이터의 흐름(Flow)**을 따라 추적하며, 각 단계별로 다음과 같은 지표를 기록하여 최종 보고서에 포함시킵니다.

*   **Input State:** 시작 시점의 데이터 상태.
*   **Process Step:** 각 로직 실행 시점의 시스템 내부 변수 변화.
*   **Output State:** 최종 DB에 반영된 결과.
*   **Deviation Check:** 입력과 출력 간의 불일치 여부 (특히 포인트 및 챌린지 값).
