# 📝 QA 시나리오 초안: 신규 사용자 온보딩 및 초기 가치 확보 플로우 검증 (MVP 핵심)

**목표:** 사용자가 앱에 진입하여 계정 생성/로그인 후, 최소한의 활동(데이터 제보 등)을 수행하고 첫 포인트 적립까지 성공적으로 완료하는 E2E(End-to-End) 프로세스의 무결성을 검증한다. (핵심 기능 1, 2, 3 통합 테스트)

---

### 🚀 [시나리오 1] 최초 가입 및 계정 설정 플로우 검증 (Auth & Onboarding)

**Precondition:** QA 담당자 또는 신규 가상 사용자 계정이 존재하지 않음.
**Test Focus:** 회원가입 프로세스의 무결성, 개인 정보 수집의 최소화 원칙 준수 여부 확인.

| 단계 | 실행 액션 (Action) | 기대 결과 (Expected Result) | 테스트 유형 | 비고 / 실패 시 리스크 |
| :---: | :--- | :--- | :--- | :--- |
| **1. 시작** | 앱 최초 실행 및 '가입하기' 버튼 클릭. | 간편 로그인(SNS 연동 등) 옵션과 이메일/전화번호 가입 옵션이 명확하게 제시되어야 함. | Positive Test | UI/UX 흐름 검증 |
| **2. 가입 (성공)** | 유효한 이메일 주소와 임시 비밀번호로 가입 완료. 이메일 인증(OTP)까지 정상적으로 수행. | 계정 생성 성공 메시지 출력 및 메인 지도로 자동 이동. 이후 '프로필 설정' 혹은 '첫 미션 안내' 팝업이 발생해야 함. | Positive Test | 데이터 유효성 검증 (Email/PW) |
| **3. 가입 (실패)** | 이미 사용 중인 이메일 주소로 재가입 시도. | "이미 등록된 계정입니다."와 같은 명확한 오류 메시지가 출력되어야 하며, 추가 정보 입력을 막아야 함. | Negative Test | 백엔드 로직 검증 |
| **4. 프로필** | 초기 가이드에 따라 사용자 이름 및 닉네임 설정 (선택 사항). | 해당 정보가 'MY 탭'의 개인 프로필 섹션에 즉시 반영되어야 함. | Positive Test | 데이터 저장/표시 무결성 |

### 📍 [시나리오 2] 핵심 가치 제공 활동 수행 검증 (Data Submission Loop)

**Precondition:** 시나리오 1이 성공적으로 완료된 상태의 사용자 계정.
**Test Focus:** 지도 데이터를 채우는 과정(제보)의 용이성, 데이터 수집 및 시스템 반영 로직 점검.

| 단계 | 실행 액션 (Action) | 기대 결과 (Expected Result) | 테스트 유형 | 비고 / 실패 시 리스크 |
| :---: | :--- | :--- | :--- | :--- |
| **1. 목표 발견** | 지도에서 '짠테크 기회'가 있는 장소(예: 저렴한 식당, 숨겨진 할인점)를 선택. | 해당 장소에 대한 상세 정보 입력 폼이 나타나며, 필수 입력 항목(사진, 가격 범위 등)이 명확히 안내되어야 함. | Positive Test | UI/UX 및 필드 유효성 검증 |
| **2. 제보 (완료)** | 가상의 짠테크 정보를 기입하고 '제보 완료' 버튼 클릭. | ① 성공 메시지 출력.<br>② 해당 데이터가 '내 제보 목록(MY 탭)'에 임시 저장된 상태로 표시됨. ③ 사용자에게 추가적인 검증/확인 요청 (예: "관리자 승인을 기다립니다."). | Positive Test | 핵심 비즈니스 로직 (데이터 수집) |
| **3. 데이터 누락** | 필수 입력 항목(예: 장소 이름, 가격대)을 비워두고 제보를 시도. | 해당 필드가 빨간색 등 명확한 경고와 함께 "필수 항목입니다."라는 안내 문구를 보여주며 전송이 차단되어야 함. | Negative Test | 유효성 검증 (Validation) |

### ✨ [시나리오 3] 인센티브 순환 및 트랜잭션 무결성 검증 (Point Earning & Tracking)

**Precondition:** 시나리오 2에서 '제보 완료'를 했으나, 아직 포인트가 적립되지 않은 상태.
**Test Focus:** 성공적인 활동에 대한 보상(포인트)의 정확한 지급 및 사용자 경험 반영 여부.

| 단계 | 실행 액션 (Action) | 기대 결과 (Expected Result) | 테스트 유형 | 비고 / 실패 시 리스크 |
| :---: | :--- | :--- | :--- | :--- |
| **1. 승인 트리거** | (Admin 역할 가정 하에) 사용자가 제보한 데이터가 '승인 대기' 상태일 때, 운영자가 해당 데이터를 수동으로 승인 처리. | ① 시스템에서 성공 알림(Notification/Pop-up)이 발생해야 함.<br>② **사용자의 포인트 잔액**이 설정된 보상 포인트(예: 10P)만큼 즉시 증가하여 'MY 탭'에 반영되어야 함. | Positive Test (Admin/Backend 연동) | **가장 중요:** 트랜잭션 무결성 검증 |
| **2. 포인트 확인** | MY 탭 또는 상단 배너의 포인트 잔액을 확인. | 기존 포인트와 적립된 포인트(예: 10P)가 합산되어 정확하게 표시되고, 내역에 "제보 활동 보상"으로 기록되어야 함. | Verification Test | 데이터 연동 검증 (MY 탭) |
| **3. 실패 트래킹** | (만약 제보 승인 로직이 오류 발생 시) 포인트 적립 과정에서 서버 에러가 발생할 경우를 가정하고 재검증. | ① 사용자에게 명확한 '시스템 오류' 메시지를 출력.<br>② 데이터(제보 정보)는 성공적으로 남아있어야 하며, 시스템은 트랜잭션을 실패로 기록해야 함. (롤백 기능 검증) | Error Handling Test | 안정성 및 회복력 검증 |
