## 📋 E2E QA 시나리오 및 테스트 케이스 목록 (Characters & Villages 모델)

**목표:** `characters` 및 `villages` 데이터 생성/업데이트 과정에서 포인트, 챌린지, 사용자 상태(MY 탭)의 데이터 무결성이 보장되는지 검증합니다.

### A. 기본 CRUD 및 데이터 정합성 테스트 (기능 구현 확인)

| ID | 시나리오 설명 | 핵심 검증 항목 | 잠재적 에러 케이스 |
| :--- | :--- | :--- | :--- |
| **TC-01** | 신규 캐릭터 생성 및 초기 포인트 할당 | `characters` 테이블에 데이터 정확히 기록, 사용자 포인트 테이블에 일치하는 만큼 지급되었는지 확인. | 포인트 누락 또는 과다 지급. |
| **TC-02** | 신규 마을(Village) 생성 및 초기 조건 설정 | `villages` 테이블의 지리적/경제적 데이터가 외부 API 또는 Seed 데이터와 정확히 매칭되는지 확인. | 필수 필드 누락으로 인한 DB 삽입 실패. |
| **TC-03** | 캐릭터/마을 간의 관계 설정 (Association) | 특정 캐릭터가 특정 마을에 속하게 하는 관계 설정이 양방향으로 올바르게 연결되었는지 검증. | 외래 키(FK) 제약 조건 위반 또는 잘못된 관계 설정. |
| **TC-04** | 데이터 업데이트 후 포인트 재계산 | 캐릭터의 '성장 레벨'이나 마을의 '수익 상태'를 업데이트했을 때, 연동된 사용자 포인트를 재계산하는 로직이 정확하게 반영되는지 확인. | 캐시 문제 또는 비동기 처리로 인한 불일치. |

### B. 트랜잭션 안정성 및 동시성 테스트 (P0 핵심 검증)

| ID | 시나리오 설명 | 핵심 검증 항목 | 잠재적 에러 케이스 |
| :--- | :--- | :--- | :--- |
| **TC-05** | **동시 포인트 지급 경쟁 (Lock Test)** | 두 사용자가 동시에 동일한 챌린지를 완료하여 포인트가 분배될 때, Lock 메커니즘이 정확히 작동하여 한 번의 트랜잭션만 성공하도록 보장하는지 검증. | **Race Condition 발생**: 중복 지급 또는 포인트 차감 오류. |
| **TC-06** | 캐릭터 상태 변경 중 데이터 충돌 방지 | 캐릭터 레벨 업그레이드(성장 과정)와 동시에 해당 캐릭터가 속한 마을의 자산 업데이트 요청이 병렬로 발생했을 때, 최종 상태가 일관성을 유지하는지 검증. | 데이터 불일치 (Dirty Read/Write). |
| **TC-07** | 트랜잭션 실패 시 롤백 검증 | 포인트 지급 또는 마을 소유권 이전 과정 중 네트워크 오류나 DB 제약 조건 위반이 발생했을 때, 전체 트랜잭션이 성공적으로 롤백되는지 확인. | 부분적 데이터 반영 (데이터 불일치). |
| **TC-08** | Lock 메커니즘의 경합 테스트 | 여러 사용자가 동시에 동일한 자원(예: 특정 마을의 자산)에 접근하려고 시도할 때, 순차적으로 처리되어 최종 결과가 예측 가능한지 검증. | 데드락(Deadlock) 발생 여부 및 시스템 응답성 확인. |

### C. 에러 핸들링 및 경계 조건 테스트 (잠재적 에러 케이스 포함)

| ID | 시나리오 설명 | 핵심 검증 항목 | 잠재적 에러 케이스 |
| :--- | :--- | :--- | :--- |
| **TC-09** | 존재하지 않는 ID로 접근 시도 | 유효하지 않은 `character_id` 또는 `village_id`를 사용하여 데이터 조회 또는 업데이트를 시도했을 때, 적절한 에러 코드(404 등)와 함께 오류가 반환되는지 확인. | Null Pointer Exception (NPE) 발생. |
| **TC-10** | 최대/최소 값 경계 조건 테스트 | 캐릭터 성장 레벨이 시스템 허용 상한선(`MAX_LEVEL`) 또는 최소값(`MIN_LEVEL`)에 도달했을 때, 추가 업데이트 시 시스템이 올바르게 거부하고 적절한 메시지를 반환하는지 확인. | 오버플로우(Overflow) 또는 무한 루프 위험. |
| **TC-11** | 외부 API 연동 실패 시 처리 | 마을 데이터나 캐릭터 정보 로딩 중 외부 서비스(예: 지도 API, 외부 데이터베이스) 호출이 실패했을 때, 시스템이 오류를 기록하고 사용자에게 명확하게 알리는지 확인. | 비정상적인 에러 메시지 노출 또는 프로세스 중단. |
| **TC-12** | 대량 데이터 삽입 시 무결성 검증 | 수백 개의 캐릭터/마을 데이터를 배치(Batch)로 삽입할 때, 전체 트랜잭션이 성공하거나 실패하는지 확인하고, 실패 시 어떤 레코드가 영향을 받았는지 추적 가능한지 검증. | 일부만 성공하고 나머지는 롤백되지 않는 데이터 손상. |
