### 📝 E2E QA 시나리오 및 테스트 케이스 최종 검토 보고

**핵심 목표:** 포인트 지급과 캐릭터 상태 변경/마을 자산 업데이트 시 데이터 충돌 방지 (Lock 메커니즘의 원자성 확보)

기존에 작성된 최소 10개 이상의 시나리오를 재검토한 결과, **트랜잭션 안정성(Lock 메커니즘 작동 여부)** 검증에 초점을 맞춘 최종 테스트 케이스 목록은 다음과 같이 확정되었습니다.

**✅ 최종 확정된 E2E QA 시나리오 (총 10개 이상):**

1.  **TC-01: 기본 포인트 지급 및 MY 탭 업데이트 동시성 검증**
    *   *목표:* 두 사용자가 동시에 포인트를 적립/지급받는 상황에서 Lock 메커니즘이 상호 배제(Mutual Exclusion)를 보장하는지 확인한다. (가장 중요)
2.  **TC-02: 캐릭터 성장 및 마을 자산 업데이트 동시성 검증**
    *   *목표:* 캐릭터 레벨업과 마을 자산 증가 요청이 동시에 발생했을 때, 최종 상태(캐릭터 데이터, 마을 자산)가 일관성을 유지하는지 확인한다.
3.  **TC-03: 트랜잭션 실패 시 롤백 검증 (Negative Test)**
    *   *목표:* 포인트 지급 중 데이터베이스 연결 오류 또는 내부 로직 실패가 발생했을 때, 관련된 모든 트랜잭션(포인트 차감/캐릭터 상태 변경)이 성공적으로 롤백되는지 확인한다.
4.  **TC-04: Lock 메커니즘 우회 시도 검증 (Security/Stability)**
    *   *목표:* 비정상적인 API 호출이나 Race Condition을 유발할 수 있는 병렬 요청 패턴을 시뮬레이션하여 시스템이 안전하게 충돌을 방지하는지 확인한다.
5.  **TC-05: 1억 챌린지 달성 및 최종 자산 반영 검증**
    *   *목표:* 목표 달성 이벤트 발생 시, 관련 포인트 지급과 '1억마을' 자산 업데이트가 동시에 정확하게 이루어지는지 End-to-End로 확인한다.
6.  **TC-06: 다중 사용자 간의 리워드 경쟁 검증**
    *   *목표:* 제한된 보상(포인트)이 있을 때, Lock 메커니즘이 설정한 순서대로 포인트가 정확하게 할당되며, 중복 지급이 발생하지 않음을 확인한다.
7.  **TC-07: 세션 만료/로그아웃 시 데이터 일관성 검증**
    *   *목표:* 사용자가 세션을 종료하거나 로그아웃할 때, 현재 진행 중인 트랜잭션 상태가 안전하게 정리되고 데이터에 반영되는지 확인한다.
8.  **TC-08: 외부 API 연동 실패 시 복구 메커니즘 검증**
    *   *목표:* 포인트 지급 과정에서 외부 시스템(만약 있다면)과의 통신이 실패했을 경우, 시스템이 안전 모드로 전환되고 오류 상태를 명확히 기록하는지 확인한다.
9.  **TC-09: 대규모 동시 요청 부하 테스트 (Stress Test)**
    *   *목표:* 수백 명의 가상 사용자가 동시에 포인트 지급/업데이트 API를 호출했을 때, 시스템이 다운되거나 데이터 불일치 없이 안정적으로 처리하는지 성능과 안정성을 동시에 검증한다.
10. **TC-10: 데이터 무결성 감사 로그 확인**
    *   *목표:* 모든 트랜잭션 성공/실패 기록(Lock 획득, 릴리스, 실패 및 롤백)이 감사 로그에 정확하게 기록되어 데이터 정합성을 입증하는지 최종적으로 검토한다.
