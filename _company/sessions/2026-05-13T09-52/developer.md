### 1단계: 인증 및 세션 관리 QA (Auth & Session Integrity)

이 단계는 사용자가 시스템에 접근하고 유효한 상태를 유지하는지 검증합니다.

| ID | 시나리오 설명 | 예상 결과 (Pass/Fail) | 핵심 검증 항목 | 성공 기준 |
| :--- | :--- | :--- | :--- | :--- |
| **QA-AUTH-001** | **정상 로그인:** 유효한 계정 정보로 로그인 시도. | Pass | 토큰 발급, 세션 데이터베이스 기록 확인. | 200 OK 응답 및 JWT 토큰 정상 수신. |
| **QA-AUTH-002** | **잘못된 인증:** 존재하지 않는 ID/PW 또는 만료된 토큰으로 로그인 시도. | Fail (Expected) | 에러 메시지, 보안 로그 기록 확인. | 401 Unauthorized 응답 및 오류 메시지 반환. |
| **QA-AUTH-003** | **세션 만료 검증:** 세션이 만료된 상태에서 API 호출 시도. | Fail (Expected) | 세션 만료 로직 정상 작동 확인. | 403 Forbidden 응답 및 재로그인 유도 화면 표시. |
| **QA-AUTH-004** | **권한 기반 접근:** 일반 사용자 계정으로 관리자 기능(예: 포인트 정책 변경)에 접근 시도. | Fail (Expected) | RBAC(Role-Based Access Control) 검증 로직 확인. | 권한이 없는 경우 접근 차단 및 적절한 에러 반환. |

### 2단계: 포인트 지급 및 트랜잭션 무결성 QA (Point Ledger Integrity)

이 단계는 비즈니스 모델의 핵심인 '선결제'와 '포인트 교환' 과정에서 데이터가 손실되거나 중복되지 않았는지 검증합니다. **원자적 트랜잭션(Atomic Transaction)**의 성공 여부를 최우선으로 확인합니다.

| ID | 시나리오 설명 | 예상 결과 (Pass/Fail) | 핵심 검증 항목 | 성공 기준 |
| :--- | :--- | :--- | :--- | :--- |
| **QA-POINT-001** | **정상 포인트 선결제:** 사용자가 교환을 위해 포인트를 선결제하고 시스템에 기록. | Pass | DB 트랜잭션(BEGIN/COMMIT) 성공 여부, 포인트 잔액 업데이트 확인. | 지급된 포인트와 사용자 계정의 잔액이 100% 일치해야 함. |
| **QA-POINT-002** | **트랜잭션 실패 (중도):** 포인트 선결제 도중 네트워크 오류 또는 서버 다운 발생 시. | Fail/Rollback (Expected) | 트랜잭션 롤백 메커니즘 작동 확인. | 시스템 상태가 이전(선결제 전) 상태로 완벽하게 복구되어야 함. |
| **QA-POINT-003** | **교환 실패:** 포인트 선결제 후, 실제 상품 교환 요청 시 데이터 불일치 발생 (예: 재고 오류). | Fail (Expected) | 교환 로직과 포인트 지급 로직 간의 연동 검증. | 포인트는 지급되지 않아야 하며, 시스템은 에러 로그를 남겨야 함. |
| **QA-POINT-004** | **잔액 무결성:** 여러 번의 선결제/교환을 반복했을 때 최종 잔액이 정확히 계산되는지 확인. | Pass | 누적된 거래 기록과 현재 포인트 잔액 간의 수학적 일치 검증. | 총 거래 금액 대비 최종 사용자 잔액은 0% 오차. |

### 3단계: 알림 및 비동기 처리 QA (Notification & Asynchronous Flow)

이 단계는 사용자가 요청한 이벤트에 대해 시스템이 적시에 정확하게 반응하고 알림을 전달하는지 검증합니다.

| ID | 시나리오 설명 | 예상 결과 (Pass/Fail) | 핵심 검증 항목 | 성공 기준 |
| :--- | :--- | :--- | :--- | :--- |
| **QA-NOTIF-001** | **성공 알림:** 포인트 교환이 성공적으로 완료된 직후, 사용자에게 즉시 알림(Push/Email) 발송. | Pass | 알림 서비스 호출 성공 및 외부 채널(FCM/SMTP) 연동 확인. | 알림 메시지가 정확하고 지연 시간은 5초 이내여야 함. |
| **QA-NOTIF-002** | **실패 알림:** 포인트 교환이 실패했을 경우, 사용자에게 명확한 오류 사유가 포함된 알림 발송. | Pass | 에러 코드 기반의 사용자 친화적인 메시지 생성 확인. | 사용자에게 "교환 실패: 재고 부족" 등 구체적 원인 제공. |
| **QA-NOTIF-003** | **배치 처리 안정성:** 대량 포인트 지급 또는 일일 리포트 생성 시 비동기 작업의 안정성 검증. | Pass | 백그라운드 워커(Worker)가 설정된 시간 내에 작업을 완료하고 상태를 업데이트하는지 확인. | 모든 배치 작업이 설정된 SLA(Service Level Agreement) 내에서 성공적으로 종료됨. |
