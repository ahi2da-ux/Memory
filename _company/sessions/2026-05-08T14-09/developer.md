테스트는 프론트엔드 동작뿐만 아니라 백엔드(Supabase) 데이터 흐름을 확인하는 통합 관점에서 설계됩니다.

## E2E 통합 테스트 케이스 (Supabase 데이터 흐름 검증)

다음은 핵심 기능별 E2E 시나리오와 필요한 검증 항목입니다. 실제 구현 시에는 이 시나리오를 기반으로 API 호출 및 DB 상태를 직접 검증하는 스크립트를 작성해야 합니다.

### 1. 인증 및 로그인 흐름 검증 (Auth Flow Verification)

**목표:** 사용자 인증(Login/Signup)이 성공적으로 이루어졌을 때 Supabase의 `auth.users` 및 관련 테이블에 정확한 레코드가 생성되고 클라이언트에 반영되는지 확인합니다.

| ID | 시나리오 | 예상 결과 (DB 상태) | 검증 포인트 |
| :--- | :--- | :--- | :--- |
| **E2E-AUTH-001** | 신규 사용자 가입 후 로그인 시도 | `auth.users`에 새 사용자 레코드가 생성되고, 세션/JWT가 발급됨 | JWT 토큰의 유효성 및 사용자의 ID 매칭 확인 |
| **E2E-AUTH-002** | 기존 사용자 로그인 | 해당 사용자의 프로필 데이터(예: 이름)가 DB에서 성공적으로 조회됨 | `profiles` 테이블 또는 연결된 테이블의 데이터 일치 여부 검증 |
| **E2E-AUTH-003** | 세션 만료 테스트 | 일정 시간 후 토큰을 사용하여 API 호출 시도 | 세션 만료 시 에러 처리 및 재인증 요구 로직 확인 |

### 2. 포인트 적립 및 관리 흐름 검증 (Points Flow Verification)

**목표:** 사용자 행동(예: 가게 제보 승인)에 따라 포인트가 정확하게 계산되어 DB에 기록되고, 사용자의 포인트 잔액이 실시간으로 업데이트되는지 확인합니다.

| ID | 시나리오 | 예상 결과 (DB 상태) | 검증 포인트 |
| :--- | :--- | :--- | :--- |
| **E2E-POINTS-001** | 특정 가게 제보 승인 후 포인트 적립 | `points` 테이블의 해당 사용자의 잔액이 이전 대비 정확히 증가했는지 확인 | 트랜잭션 무결성 및 데이터 증가량 검증 |
| **E2E-POINTS-002** | 여러 번의 적립/차감 반복 테스트 | 복합적인 거래(적립, 차감) 후 최종 잔액이 수학적으로 일치하는지 확인 | 포인트 계산 로직의 정확성 (오버플로우, 음수 방지 포함) |
| **E2E-POINTS-003** | 포인트 한도 초과 시도 | 최대 한도를 초과하려는 시도 시 API 응답 및 DB 레코드 상태 확인 | 비즈니스 규칙(Constraint) 적용 여부 검증 |

### 3. MY 탭 데이터 흐름 검증 (Data Sync Verification)

**목표:** 사용자 프로필, 포인트, 챌린지 등 다양한 데이터가 Supabase의 기준 데이터를 따라 클라이언트에 정확하게 동기화되는지 확인합니다.

| ID | 시나리오 | 예상 결과 (DB 상태) | 검증 포인트 |
| :--- | :--- | :--- | :--- |
| **E2E-MYDATA-001** | 사용자 프로필 데이터 로드 | 로그인 후 MY 탭에서 표시되는 모든 필드가 Supabase의 `profiles` 테이블과 일치하는지 확인 | 데이터 매핑 및 조회 권한(RLS) 검증 |
| **E2E-MYDATA-002** | 챌린지 진행 상태 동기화 | '1억 챌린지'와 같은 핵심 목표 관련 데이터가 DB의 상태와 정확히 일치하는지 확인 | 비즈니스 로직과 실제 저장된 상태의 정합성 검증 |
| **E2E-MYDATA-003** | 실시간 업데이트 확인 | 백그라운드에서 포인트나 알림이 변경되었을 때, 프론트엔드가 즉시(또는 지정된 시간 내에) 반영하는지 확인 | Realtime/Webhook 기반 데이터 흐름의 지연 시간 검증 |

---
**실행 가이드:** 개발팀은 위 시나리오를 기반으로 각 단계별 API 엔드포인트 호출과 Supabase 테이블(`auth.users`, `public.points`, `public.profiles` 등)에 대한 직접적인 쿼리 결과를 비교하는 테스트 스크립트를 작성해야 합니다. 특히 트랜잭션이 걸린 포인트 적립 과정에서 DB의 상태 변화를 중점적으로 추적해야 합니다.
