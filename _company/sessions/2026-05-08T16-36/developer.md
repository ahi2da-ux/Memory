## 📝 Acceptance Test Cases (수락 테스트 사례) 보고서

본 문서는 **'가치 생성 루프 완성도(Risk A)'** 및 **'ROI 정량화(Risk B)'** 기준을 충족하는 최종 출시 승인 조건에 맞춰, 현재 진행 중인 E2E 테스트 케이스를 개발팀이 수락할 수 있도록 구체화한 항목입니다.

### 1. 테스트 범위 정의 (Scope Definition)
*   **목표:** 로그인/Auth, 포인트 적립, 챌린지 연동 데이터 흐름의 Supabase 계정 기준 완벽 동기화 검증.
*   **핵심 검증 대상:** 사용자 경험(UX)이 아닌 **데이터 정합성(Data Integrity)**과 **수익화 루프 완성도(Loop Closure)**에 초점을 맞춥니다.

### 2. Acceptance Test Cases (ATCs) 상세 정의

아래 테스트 케이스는 Business 에이전트가 제시한 KPI 프레임워크를 기반으로, 각 데이터 흐름의 성공 여부를 수치적으로 입증하도록 설계되었습니다.

| ID | 검증 목표 (Goal) | 측정 기준 (Metric Link) | E2E 시나리오 (Test Scenario) | 예상 결과 (Expected Result) | 승인 조건 (Acceptance Criteria) |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **TC-01** | 인증 흐름의 무결성 검증 | Auth Flow Success Rate | 1. 새로운 사용자 가입 $\rightarrow$ 로그인 성공 (Session 생성) | 세션 토큰이 정상적으로 발급되고 Supabase 계정에 매핑됨. | 로그인 시도 시, 인증 실패 오류 없이 즉시 세션 활성화 및 데이터 접근 허용. |
| **TC-02** | 포인트 적립의 정확성 검증 | Loop Start Point 확보 | 1. 특정 가게에서 '정보 제보' 액션 수행 $\rightarrow$ 포인트 적립 요청 트리거 확인. | 제보 완료 즉시, 시스템이 지정된 포인트 규칙에 따라 포인트를 DB에 기록함. | 적립된 포인트 수와 기록 시간(Timestamp)이 Supabase 데이터와 100% 일치해야 함. |
| **TC-03** | 포인트 전환의 정확성 검증 | Loop Closure Point (직접 수익) | 1. 적립된 포인트를 사용하여 현장 경험을 기반으로 '포인트 구매/사용' 시도. | 사용자가 요청한 포인트 차감 및 서비스 이용 권한이 정상적으로 부여됨. | 포인트 잔액 감소와 서비스 접근 권한 변화가 동기화되어야 하며, 시스템 오류 없이 완료되어야 함. |
| **TC-04** | 챌린지 데이터의 안정성 검증 | Loop Core Activity 발생 | 1. 특정 챌린지에 참여 $\rightarrow$ 목표 달성 조건(예: 인증샷 업로드) 수행. | 챌린지 상태가 '진행 중'에서 '완료'로 정확히 변경되고, 관련 데이터(사진/로그)가 저장됨. | 완료 시점의 데이터는 외부 API 호출 없이 Supabase 내에서 완벽하게 종결되어야 함. |
| **TC-05** | MY 탭 데이터 흐름 검증 | 전체 루프 완성도 (Risk A) | 1. 모든 상기 액션(제보, 적립, 전환, 챌린지)을 수행한 후 $\rightarrow$ 'MY 탭' 데이터 로드 시점 확인. | 모든 활동 기록이 MY 탭에 누락 없이 집계되어 표시됨. | **데이터 불일치율 0%**. (가장 중요한 출시 기준) |

### 3. 개발팀 실행 계획 (Action Plan for Development Team)
1.  **데이터 로깅 검토:** TC-02, TC-04의 경우, 포인트 적립 및 챌린지 완료 시점의 Supabase 트랜잭션 로그를 직접 확인하여 데이터 불일치 여부를 1차로 점검합니다.
2.  **트랜잭션 안정성 보강:** TC-03(포인트 전환) 단계에서 발생하는 모든 DB 쓰기/읽기 과정에 대해 ACID(원자성, 일관성, 격리성, 지속성) 속성이 완벽히 보장되는지 쿼리 레벨에서 검증합니다.
3.  **최종 승인 기준 적용:** TC-05의 데이터 흐름이 모든 E2E 테스트를 통과할 경우에만 '가치 생성 루프 완성도' 항목은 **'통과(Pass)'**로 간주하고 출시 준비를 진행합니다.
