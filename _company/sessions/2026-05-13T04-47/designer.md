(담당 에이전트: 🎨 Designer (리드) $\rightarrow$ 💻 코다리 (검토/최종 승인))

**목표:** 지금까지 확정된 모든 UI 컴포넌트, 애니메이션, 인터랙션에 대한 **개발자 친화적인 최종 명세서(Specification)**를 작성하고, 이를 개발팀이 바로 사용할 수 있는 형태로 패키징한다. 이 문서는 곧 '디자인-개발 계약서' 역할을 수행합니다.

**핵심 초점:**
1.  **컴포넌트 레벨의 상세 스펙화:** 색상 코드(HEX), 폰트 크기(px/rem), 그림자 깊이, 상태별 변화(Hover, Active, Disabled)까지 전부 정의.
2.  **인터랙션 명세:** 단순한 레이아웃을 넘어, 버튼 클릭 시 발생하는 애니메이션 시간(ms)과 방식(Easing Curve) 등 **마이크로 인터랙션** 스펙화. (이것이 사용자의 '신뢰성' 체감도를 결정합니다.)
3.  **개발 검증 체크리스트:** 개발팀이 구현 단계에서 놓치기 쉬운 접근성(A11y), 반응형 디자인 Breakpoint, 성능 최적화 항목을 명시하여 QA 프로세스를 강화합니다.

### 🛠️ 세부 실행 계획 및 산출물

#### Task 1: 컴포넌트 라이브러리 명세서 작성 (Designer 주도)
*   **내용:** 모든 핵심 요소(버튼, 입력창, 카드, 네비게이션 바 등)를 나열하고, 각 컴포넌트에 대한 **State-by-State 스펙**을 정의합니다.
*   **결과물 형식:** `[파일명] / [컴포넌트 이름] / [상태(Default/Hover/Active/Error)] / [속성 값]` 형태로 구조화된 Markdown 또는 Spec Sheet 파일.

#### Task 2: 시스템 워크플로우 및 트랜지션 정의 (Designer + 코다리 검토)
*   **내용:** 사용자가 앱을 사용할 때의 주요 화면 이동(예: 온보딩 $\rightarrow$ 홈 $\rightarrow$ 제보/수익화 페이지)에 필요한 애니메이션 흐름과 전환 효과를 명시합니다.
*   **코다리 역할:** 이 트랜지션이 기존 E2E QA 시나리오와 충돌하지 않는지, 성능상 부하가 크진 않은지 기술적으로 검토하고 피드백을 제공해야 합니다.

#### Task 3: 랜딩 페이지 최종 개발 요구사항 정의 (Designer 주도)
*   **내용:** 확정된 3가지 LP 시안(A/B 테스트용) 각각에 대해, '필수 구현 컴포넌트', 'API 연동 지점', 그리고 '최소 실행 가능한 MVP 기준'을 명확히 합니다. 개발 범위를 최소화하고 속도를 높이는 데 집중합니다.

## 📜 1. 목표 및 범위 정의

본 문서는 '짠테크' MVP의 최종 출시를 위한 모든 UI/UX 컴포넌트, 인터랙션, 그리고 기술적 요구사항을 정의하는 공식 설계 문서입니다. 개발팀은 본 명세서를 기반으로 코딩하며, 디자인 팀과 QA 팀은 이 스펙에 근거하여 테스트해야 합니다.

### 🎯 핵심 가치 재확인
*   **핵심 메시지:** 신뢰성(Trust)과 지능적 성장(Smart Growth). (단순 절약을 넘어선 '자산 형성 과정'을 시각화.)
*   **톤앤매너:** 미니멀리즘, 정제된 데이터 중심의 차분함.

## 🛠️ 2. 컴포넌트 라이브러리 명세서 (Atomic Design)

모든 요소는 재사용성을 최우선으로 하며, 다음 스펙을 준수합니다.

### A. 타입োগ্রাফ이(Typography)
*   **메인 폰트:** Pretendard (또는 Noto Sans KR). 가독성 및 현대적 느낌 강조.
*   **헤딩 H1 (최대 제목):** 32px / Bold / Color: #0F172A (짙은 남색)
*   **본문 P (Body Text):** 16px / Regular / Line-Height: 1.5em / Color: #334155 (어두운 회색)
*   **CTA 버튼:** 18px / SemiBold

### B. 컬러 팔레트 및 코드
| 용도 | 색상명 | HEX Code | 역할/비고 |
| :--- | :--- | :--- | :--- |
| **Primary** (주요 액션) | Money Green | `#059669` | 긍정적 행동(제보, 성공). 가장 중요한 CTA 배경색. |
| **Secondary** (강조/데이터) | Accent Blue | `#3b82f6` | 데이터 차트 강조, 마일스톤 표시. Primary 보완 역할. |
| **Background** | Light Grey | `#F7FAFC` | 전체 배경색. 시각적 피로도 감소 목적. |
| **Text/Dark** | Charcoal Black | `#1E293B` | 기본 텍스트 색상. 높은 대비(Contrast) 확보. |
| **Warning** (경고/오류) | Danger Red | `#dc2626` | 오류 메시지, 주의사항. 반드시 눈에 띄게 처리. |

### C. 인터랙션 컴포넌트 스펙

#### 1. Button (`<Button>`)
*   **Base State:** Background: Primary Green (#059669), Color: #FFFFFF, Padding: 12px 24px, Border-Radius: 8px.
*   **Hover State:** Background: Darker Green (#047857), Opacity: 0.95. (미묘한 어두워짐 효과)
*   **Active State:** Scale: 0.98 (눌리는 듯한 물리적 피드백). Shadow: 0px.

#### 2. Input Field (`<InputField>`)
*   **Default State:** Border: 1px solid #D1D5DB, Background: #FFFFFF. Placeholder Color: #9CA3AF.
*   **Focus State (⭐ 중요):** Border: 2px solid Accent Blue (#3b82f6). Shadow: Focus-ring effect (z-index 높게 처리하여 시각적 강조).

## ✨ 3. 핵심 트랜지션 및 애니메이션 스펙

애니메이션은 '신뢰성'과 '유기적인 성장'을 표현하는 수단입니다. 빠르지만 부드러워야 합니다.

*   **화면 전환 (Page Transition):** 모든 주요 화면 이동 시, 좌측에서 오른쪽으로 250ms 동안 페이드-인/슬라이드 효과 적용.
*   **데이터 로딩 (Skeleton Loading):** 콘텐츠가 로딩되는 영역은 반드시 스켈레톤 UI를 사용하며, 최소 150ms 간격의 '점멸(Pulsing)' 애니메이션을 적용하여 체감 대기 시간을 줄입니다.
*   **성장 표시 (Growth Indicator):** 캐릭터 레벨업/자산 증가 시, 숫자 변화는 단순한 점프가 아닌 **'Spring Physics' 기반의 부드러운 튕김 효과**를 사용하여 성장의 기쁨과 동기를 부여합니다.

## 🗺️ 4. 랜딩 페이지(LP) 개발 요구사항 (MVP 최소 기능 기준)

확정된 3가지 LP 시안은 다음 6개 섹션을 중심으로 구현하며, 각 섹션별 기술적 명세는 다음과 같습니다.

1.  **Hero Section:** *[필수]* 핵심 가치 메시지와 CTA 버튼(Primary Button 스펙 준수).
2.  **문제 제기 (Pain Point):** *[선택]* 사용자 공감을 얻을 수 있는 데이터 기반의 통계 자료 섹션. (이미지/차트 컴포넌트 사용)
3.  **해결책 제시:** *[필수]* '짠테크맵'이 어떻게 이 문제를 해결하는지, 핵심 기능을 3가지 아이콘과 간략 설명으로 정리.
4.  **How It Works (작동 방식):** *[필수]* 온보딩/제보 과정을 3단계의 화살표 기반 흐름도로 시각화. (애니메이션 적용 지점)
5.  **신뢰 구축 (Proof/Testimonials):** *[최우선]* 베타 테스터 후기 및 '안정성 검증 완료' 배지 삽입 공간. **개발팀은 이 배지를 가장 눈에 띄게 처리해야 합니다.**
6.  **CTA Footer:** 최종 행동 유도 섹션. (다운로드 버튼, 고유 UTM 링크 필수)

### ✅ 개발 체크리스트 및 승인 사항
*   [ ] **반응형 설계:** 모든 컴포넌트는 모바일(375px), 태블릿(768px), 데스크톱(1440px) 기준으로 Breakpoint를 명시하여 구현.
*   [ ] **접근성 (A11y):** 모든 이미지에 Alt Text 필수, 색상 대비율(Contrast Ratio) AA 레벨 이상 확보.
*   [ ] **API 연동:** 사용자 제보/로그인 관련 API 엔드포인트와 데이터 스키마는 개발팀이 정의한 [통신 규격 문서]를 따름.
